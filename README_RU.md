# FIBRO TEXTILE AGENCY — сайт с 3D-анимацией и админ-панелью

Это исходный проект на React + Vite + Three.js/React Three Fiber + Supabase. В нём есть:
- интерактивная 3D-сцена с катушкой пряжи, вращающимися кольцами и частицами;
- дополнительные 3D-сцены в карточках материалов;
- адаптивные страницы компании, ассортимента, подхода и контактов;
- защищённая админ-панель для управления каталогом, фотографиями и контактными данными;
- Supabase Auth, таблицы, Row Level Security (RLS) и правила загрузки изображений.

## Важно перед запуском
Текст и товары в стартовом каталоге — шаблонные примеры на основе предоставленной информации. До передачи владельцу подтвердите название компании, адрес, телефон, перечень материалов и все коммерческие заявления. Не добавляйте на сайт цены/наличие, если компания их не подтвердила.

## 1. Создать Supabase-проект
1. Откройте https://supabase.com/ и войдите/зарегистрируйтесь.
2. Создайте новый проект и сохраните пароль базы данных в надёжном месте.
3. В панели проекта откройте **SQL Editor → New query**.
4. Откройте файл `supabase/schema.sql`, скопируйте весь SQL и запустите его кнопкой **Run**.
5. В **Project Settings → API** (или Connect) скопируйте Project URL и публичный anon/publishable key. Никогда не используйте `service_role` key в браузере.

## 2. Создать администратора
1. В Supabase откройте **Authentication → Users → Add user**.
2. Создайте учётную запись с email и сильным паролем. Если доступна опция подтверждения email, подтвердите/создайте пользователя по правилам вашего проекта.
3. Откройте **SQL Editor** и выполните запрос, заменив email на точный email созданного пользователя:

```sql
insert into public.admin_users (user_id)
select id from auth.users where lower(email) = lower('admin@example.com')
on conflict (user_id) do nothing;
```

4. Если строка не добавилась, проверьте email в Authentication → Users. Не выдавайте права администратора посторонним аккаунтам.
5. Не вставляйте пароль, service role key или другие секреты в исходный код сайта.

## 3. Запустить локально
Установите Node.js LTS: https://nodejs.org/

В терминале внутри папки проекта:
```bash
cp .env.example .env
```
Откройте `.env` и заполните значения:
```env
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_OR_PUBLISHABLE_KEY
```
В Windows можно просто создать файл `.env` вручную, скопировав строки из `.env.example`.

Затем:
```bash
npm install
npm run dev
```
Vite покажет локальный адрес, обычно `http://localhost:5173`.

Проверка production-сборки:
```bash
npm run build
npm run preview
```

## 4. Опубликовать и получить настоящую ссылку (Vercel)
1. Создайте аккаунт на https://vercel.com/
2. Создайте приватный GitHub-репозиторий на https://github.com/ и загрузите туда файлы проекта (не загружайте `.env`).
3. В Vercel выберите **Add New → Project** и импортируйте репозиторий.
4. Добавьте в Vercel → **Settings → Environment Variables**:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
5. Нажмите **Deploy**. Vercel выдаст настоящую ссылку вида `https://your-project.vercel.app`.
6. После каждого обновления файлов Vercel может автоматически собирать новую версию из GitHub.
7. В Supabase → Authentication → URL Configuration задайте опубликованный URL в **Site URL** и добавьте его в **Redirect URLs**, если используете email-ссылки/восстановление пароля.
8. Откройте опубликованный сайт, нажмите маленькую иконку замка в шапке или ADMIN внизу и войдите с админской учётной записью.

Пока проект не загружен в ваш аккаунт Vercel/Supabase, настоящую публичную ссылку создать нельзя. Нужен доступ владельца к этим аккаунтам либо чтобы владелец сам выполнил публикацию. Я не могу безопасно угадывать или создавать логины/пароли за владельца.

## 5. Админ-панель
- Иконка замка в шапке открывает вход.
- После входа появятся разделы **Каталог товаров** и **Контакты сайта**.
- Можно добавить/изменить/опубликовать/снять с публикации товары, загрузить фото и удалить товары из базы.
- В разделе контактов можно обновить телефон, WhatsApp, адрес, email и подпись бренда.
- Права редактирования проверяются в базе данных Supabase через таблицу `admin_users` и RLS, а не только скрытием кнопок на сайте.

## Технические замечания
- Используется только публичный Supabase anon/publishable key во фронтенде. Безопасность записи обеспечивают RLS-политики.
- Публичные фотографии находятся в public storage bucket; загружать/менять/удалять их могут только администраторы.
- В этом starter-проекте не включены управление заказами, платежи, складские остатки или формы обратной связи с отправкой писем.
- Трёхмерные эффекты требуют современного браузера и WebGL. При необходимости можно уменьшить качество рендера для слабых телефонов.
- Проверяйте `npm run build` перед публикацией.
